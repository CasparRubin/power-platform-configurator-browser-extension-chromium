# Power Platform Configurator

**Public summary** (matches manifest `description`, max 132 characters): Choose classic or new designer for Power Automate flow/run URLs. Control survey flags. Reveal or enable Power Apps form elements. Survey **Hide** / **Show**, `v3` flags, and full behavior are documented below and on the Helvety Store listing (`POWER_PLATFORM_CONFIGURATOR_STORE_SHORT_DESCRIPTION`).

That one-line blurb covers both popup product areas. The popup **Power Automate** tab still supports survey **Show**, which normalizes an existing `v3survey` key on the URL to `true` without adding the parameter when it is absent—see **What it does** and **Known limitations** for the full rules.

Chrome/Edge extension (Manifest V3) that **keeps flow and run links opening in the editor you choose** while the extension is active: classic (`v3=false`) or new designer (`v3=true`), even when Microsoft links omit or flip the flag. You can **pause** anytime (extension stays installed; no URL rewrites or DNR rules). **Declarative Net Request** rules only add or replace the **`v3`** query parameter on matching navigations; the **service worker** and **content script** apply the full URL policy from sync, including **`v3survey`** from the popup **Power Automate** tab (sync key `v3surveyEnabled`). Microsoft sometimes uses **`v3survey`** for an in-product **classic-designer survey** prompt. **Hide** (default, sync `"false"`) sets **`v3survey=false`** on rewrites (adds the param if missing). **Show** (sync `"true"`) normalizes any existing `v3survey` query keys on the URL to a single **`v3survey=true`** and does **not** add the param when it is absent.

On **model-driven Power Apps** hosts (Dataverse organization suffixes in [Microsoft's region table](https://learn.microsoft.com/en-us/power-platform/admin/new-datacenter-regions), snapshot checked July 17, 2026—e.g. `{org}.crm17.dynamics.com`, `{org}.crm.dynamics.cn`, `{org}.crm.microsoftdynamics.de`—plus `apps.powerapps.com`), the popup **Power Apps** tab offers **Keep hidden** / **Reveal hidden elements** and **Keep disabled** / **Enable disabled controls** radio settings. Choices persist in **`chrome.storage.sync`** (`powerAppsHiddenFields`, `powerAppsReadOnly`) and are reapplied on completed tab loads, preference changes, popup apply, `popstate`, and URL changes caught by the short-lived startup watchdog. Late same-document `pushState` / `replaceState` navigation may require a page reload. Those active modes inject a self-contained MAIN-world script that calls the Xrm Client API on each eligible **record form** (client-side only; canvas apps are not supported). **Keep hidden** stops automatic revealing; **Keep disabled** stops automatic unlocking. Reload open forms to restore platform defaults after turning either behavior off. A floating **`SettingsStatusAlert`**, anchored below the tab bar for the active product tab only, reports success counts, informational guidance when the preference saved but could not be applied to the active tab, or specific errors (wrong host, permission failure, or background messaging failure).

## What it does

- Runs on Microsoft Power Automate hosts:
  - `https://*.powerautomate.com/*`
  - `https://flow.microsoft.com/*`
- Only changes URLs whose path contains `/flows/` or `/runs/` (and only while enforcement is **not** paused).
- **Toolbar popup** (React + Tailwind + Base UI): `src/popup/index.html` defines Chrome’s maximum popup viewport (**800×600** px), while `popup-layout.ts` fills that viewport. Header shows the packaged **`ppconfigurator_*`** icon and **Power Platform Configurator** with the manifest version (`PopupHeader` wraps `@helvety/extension-chrome/popup-header`). Tabs: **Power Automate**, **Power Apps**, and **About**, with a filled active state and red underline. A zero-height anchor after the tab bar positions a floating **`PopupNotificationRegion`** / **`SettingsStatusAlert`** at the panel’s upper right for the **active** product tab only; it renders nothing when idle and does not move panel content. Tab bodies use **`SettingsTabPanel`** (shared scroll shell: `TAB_PANEL_HOST_CLASS` + stacked `TabsContent` layers in `App.tsx` (with classes from `popup-layout.ts`), not three flex-split bands). All settings use **`SettingsChoiceRow`** / **`SettingsSectionHeader`** with local spacing tokens from **`popup-layout.ts`** (`settingsChoiceRowClass`, `SETTINGS_RADIO_GROUP_CLASS`, …)—not the legacy `@helvety/extension-chrome/popup-shell` row helper. Each **`SettingsChoiceRow`** wraps the radio, title, and description in one **`Label`** so the full row is clickable. Section descriptions use quiet supporting text by default; the Power Apps disabled-controls security note opts into a bordered **`SettingsInfoAlert`**. **`SettingsBusyHint`** on section headers appears only when the floating notification is idle, avoiding duplicate **Saving…** / **Applying…** copy. Before the main UI renders, **`App.tsx`** loads flow designer, survey, and Power Apps prefs in one **`POPUP_SYNC_SETTINGS_KEYS`** read (popup theme via **`usePopupTheme`** separately). The **Power Automate** tab combines flow designer (**Classic Designer**, **New Designer**, or **Paused**) and survey prompt Hide/Show (`v3survey`). Your designer choice is stored in `chrome.storage.sync` under `enforcedV3` as `"true"`, `"false"`, or `"off"` and applied in the service worker, content script, and DNR layer. Preferences use `chrome.storage.sync`; they sync across signed-in browser profiles when browser sync is enabled and otherwise remain local to that profile ([Chrome `storage` docs](https://developer.chrome.com/docs/extensions/reference/api/storage/)). The service worker mirrors that preference on the **browser toolbar icon** as a small **C** / **N** badge (via `chrome.action`), or clears the badge while **Paused**. The **Power Apps** tab uses the same radio-card pattern for hidden form elements and disabled controls. The service worker and **`content-powerapps.js`** re-apply active revealing/enabling preferences after supported Dataverse tab loads, preference changes, and detected URL changes via **`applyPowerAppsPreferencesOnTab`** (`chrome.scripting.executeScript`, MAIN world, all permitted frames, self-contained **`powerAppsFormActionInPage`** in `src/powerapps/`). **`App.tsx`** owns Power Apps status timers; saves and active-tab apply results surface in the floating notification (`persist-powerapps-preference.ts`, `powerapps-client.ts`, `powerapps-router.ts`). **About** ends with a **Developer** block (Helvety logo and link to [helvety.com](https://helvety.com)). **Popup appearance** (About tab: **Light** or **Dark**; first open picks from the OS, then the choice is stored) lives in **`chrome.storage.local`** under `popupThemePreference` so it stays on this device and does not sync across signed-in browsers. Before React, `@helvety/extension-chrome/theme-boot` applies the OS `prefers-color-scheme` to `<html>` only (MV3 extension CSP; no inline script); the popup then applies the saved **Light** / **Dark** from storage via `usePopupTheme`.
- **Save feedback (Power Automate):** phased messages (**Saving preference…** → **Refreshing the active Power Automate tab…** when applicable → **Saved.** / **Saved. Reloaded the active flow or run page.** / **Saved. Reload the flow or run page to apply.**) appear in the floating notification during **`chrome.storage.sync.set`** and, separately, during an optional **`chrome.tabs.reload`** of the active tab in the last-focused window when that tab is a **flow/run** target (`src/popup/reload-focused-target-tab.ts`; returns whether reload ran, for auto-dismiss timing). Flow designer and survey **radio groups stay enabled** during saves. **Tab triggers stay enabled** so you can switch tabs during a reload. Rapid toggles on the same surface are **serialized** (one **`createAsyncQueue`** each for flow designer vs survey saves in `src/popup/sync-write-queue.ts`) so `chrome.storage.sync.set` calls cannot reorder. Shared save/reload logic lives in `src/popup/persist-policy-preference.ts` (wired from `App.tsx`; status strings in `persist-status-messages.ts`).
- **Save feedback (Power Apps):** **`App.tsx`** owns hidden/enabled state, status timers, and busy flags from the shared preload; **`PowerAppsPanel`** is controlled and writes **`powerAppsHiddenFields`** and **`powerAppsReadOnly`** via **`persist-powerapps-preference.ts`** (serialized with **`createAsyncQueue`** in the panel). Radios stay enabled during save/apply. When revealing or enabling is active, the floating notification shows **Saving preference…** then **Applying…** with results from the active tab (`APPLY_PREFERENCES_ACTIVE_TAB`, including short in-popup retries). Formatted apply outcomes from **`format-powerapps-preferences.ts`** supply explicit alert **`variant`** values; progress messages use inference when no variant is supplied. Retryable form-context or injection misses use informational copy that says the preference saved but could not be applied to the active tab and asks the user to open or reload a model-driven record form. Choosing **Keep hidden** or **Keep disabled** stops only the corresponding automatic action; reload open record forms to restore platform defaults. Non-retryable host, permission, and messaging failures stay red with specific recovery guidance. The service worker and **`content-powerapps.js`** reapply whichever revealing/enabling modes remain active after completed loads, preference changes, and URL changes detected by `popstate` or the short-lived watchdog. In **development** popup builds, optional `console.log` traces use the prefix `[power-platform-configurator] [popup]` (`policy-popup-log.ts` and the reload helper; gated by `import.meta.env.DEV`).
- **Declarative Net Request** static rulesets only add or replace the **`v3`** query parameter on matching **main_frame** requests (they do not read **`v3surveyEnabled`** from storage and do not change **`v3survey`**).
- The **service worker** and **content script** read `enforcedV3` and `v3surveyEnabled` from sync and run `PowerAutomateUrlPolicy`: they keep **`v3`** aligned with your editor choice. **`v3survey`**: **Hide** (default, sync `"false"`) sets **`v3survey=false`** (adds if missing) on rewrites. **Show** (sync `"true"`) collapses duplicate keys to a single **`v3survey=true`** only when the URL already had `v3survey`; it never adds the param when absent. Sync key: `v3surveyEnabled` (`"true"` / `"false"`).
- Uses semantic URL dedupe to avoid rewrite loops on equivalent `/flows/new` URLs (for example `%20` vs `+` encoding differences).
- **Layered enforcement** (aligned with Chromium MV3 best practices):
  - **Layer 1:** `declarativeNetRequest`: two static rulesets (`dnr-classic-editor.json`, `dnr-new-designer.json`); each rule’s `queryTransform` only sets **`v3`**. When enforcing, **exactly one** ruleset is enabled via `updateEnabledRulesets`; when **paused**, **both** are disabled. When the service worker loads (cold start, wake from idle, or after an extension update), it reconciles enabled rulesets with storage (Chromium does not persist which static rulesets were enabled across extension updates; the manifest defaults apply until the service worker runs again; see [Declarative Net Request](https://developer.chrome.com/docs/extensions/reference/api/declarativeNetRequest)).
  - **Layer 2:** Background `webNavigation` (`onCommitted`, `onHistoryStateUpdated`) runs the full stored URL policy (including **`v3survey`** per **Hide** / **Show**) via `tabs.update` when enforcement is active (same canonicalization as the content script; no-op when paused).
  - **Layer 3:** Content script at `document_start` for startup and `popstate` canonicalization, with short-lived polling + `MutationObserver` fallbacks when enforcement is active (polling/observer are not started while paused). Reliable page-world History API SPA transitions are handled by Layer 2 `webNavigation.onHistoryStateUpdated`; isolated-world History wrappers do not intercept page-world `pushState` / `replaceState`. `MutationObserver` callbacks are coalesced to at most one canonicalization per animation frame to reduce main-thread churn.

## Helvety workspace packages (`npm install`)

The popup imports **`@helvety/extension-chrome`**, **`@helvety/ui`**, and **`@helvety/shared`** from a vendored copy under **`.helvety/`** (gitignored). `preinstall` runs `scripts/ensure-helvety.mjs`:

- If **`../helvety`** exists: **copies** `packages/{shared,ui,brand,extension-chrome,config}` into `.helvety/packages/` (never symlinks into the monorepo, so `patch-helvety-workspace-deps.mjs` cannot mutate sibling repos). The copy **skips** `node_modules`, `.turbo`, `coverage`, `dist`, and `.next` so Bun workspace symlinks / build caches are not vendored.
- Otherwise: reuses or shallow-clones `.helvety/` from GitHub, then patches `workspace:*` → `file:../` inside **`.helvety/packages` only**.

Popup primitives (tabs, `RadioGroup` / `RadioGroupItem`, labels) come from **`@helvety/ui`**, not app-local `src/components/ui`. Local shadcn-style **`Alert`** lives in **`src/popup/components/ui/alert.tsx`** for **`SettingsStatusAlert`** and **`SettingsInfoAlert`**. Shared padding, section rhythm, choice-card rows, the zero-height notification anchor and top-right region, tab shells (**`SettingsTabPanel`**), and **`SettingsBusyHint`** live in **`src/popup/popup-layout.ts`** and **`SettingsChoiceRow`** / **`SettingsSectionHeader`** (this repo—not `@helvety/extension-chrome/popup-shell`). User-facing save strings are centralized in **`persist-status-messages.ts`**; Power Apps apply outcomes are formatted in **`format-powerapps-preferences.ts`**. `components.json` maps shadcn CLI aliases to local popup components and Helvety `ui` / `utils`.

## Build and load (development)

Source lives under `src/`. The loadable extension is produced in **`dist/`** after a build.

1. Install dependencies and build:

   ```bash
   npm install
   npm run build
   ```

2. Open `chrome://extensions` (Chrome) or `edge://extensions` (Edge), enable **Developer mode**, click **Load unpacked**, and select the **`dist`** folder (not the repository root).

3. After changing anything under `src/`, `public/`, or build config, run `npm run build` again before reloading the extension in the browser (the unpacked folder must be **`dist/`**, which is replaced on each full build).

## Browser compatibility

- Supported and documented: **Google Chrome 111+** and current Chromium-based **Microsoft Edge** when third-party extension stores are allowed. Other Chromium-based browsers may work but are not currently tested.
- The manifest declares `minimum_chrome_version` **111** for Chrome. Edge should use Chromium 111 or newer; the Chrome manifest field does not enforce an Edge minimum. The floor is set by the popup’s OKLCH design tokens and `color-mix()` usage. Power Apps enforcement separately uses `chrome.scripting.executeScript` with `world: "MAIN"`, which predates Chromium 111.
- Requires: `declarativeNetRequest`, `webNavigation`, `scripting`, `storage`, and `host_permissions` for Power Automate and model-driven hosts (per-cluster patterns such as `https://*.crm17.dynamics.com/*` for `{org}.crm17.dynamics.com`, plus `apps.powerapps.com`). Chrome rejects multi-wildcard hosts like `*.*.dynamics.com`. Power Automate content scripts use `popstate`, short-lived polling, and `MutationObserver`; background `webNavigation` handles page-world History API SPA changes. Power Apps uses **`content-powerapps.js`** (ISOLATED world) for startup, `popstate`, preference changes, and a short-lived URL watchdog, plus background `tabs.onUpdated` after completed loads; **`chrome.scripting.executeScript`** applies reveal/enable actions in the MAIN world. See [tabs](https://developer.chrome.com/docs/extensions/reference/api/tabs) and [scripting](https://developer.chrome.com/docs/extensions/reference/api/scripting).

## Implementation notes

- **Service worker listeners** (`webNavigation`, `tabs.onRemoved`, `storage.onChanged`, `runtime.onInstalled`) are registered at the **top level** of `background.ts`, per Google's MV3 guidance (avoid registering listeners only inside async callbacks). `webNavigation` handlers are `async` and **`await policyQueue.awaitReconcileCaughtUp()`** before running URL logic, so handling waits for the initial `chrome.storage.sync` reconciliation attempt. If storage cannot be read, the failure is logged and module defaults remain in place (see `src/policy-load-queue.ts`).
- **Popup policy saves** (`persist-policy-preference.ts`, called from `App.tsx`): radio controls remain interactive while writes run; after each successful `chrome.storage.sync.set` for `enforcedV3` or `v3surveyEnabled`, the sync-write busy flag clears. A floating **`SettingsStatusAlert`**, anchored below the tab bar for the active product tab only, shows **Saving preference…** / **Refreshing the active Power Automate tab…** while work runs—section **`SettingsBusyHint`** labels hide during that time to avoid duplicate copy. The popup then awaits `reloadFocusedTargetTabIfApplicable` (when enforcement is not **Paused**) and shows **Saved.**, **Saved. Reloaded the active flow or run page.**, or **Saved. Reload the flow or run page to apply.** depending on whether the active tab in the last-focused window was reloaded. The helper’s **boolean** return still drives status auto-dismiss timing (longer only when `chrome.tabs.reload` actually ran). Flow designer and survey saves each use a **`createAsyncQueue`** tail so rapid clicks serialize storage writes. Pending dismiss timers are cleared when a new save starts or the popup unmounts.
- **`reconcileFromStorage()`** is queued by **`createPolicyLoadQueue`**: an initial run happens when the service worker loads; further runs are chained from `chrome.storage.onChanged` (for `enforcedV3` / `v3surveyEnabled`) and from `chrome.runtime.onInstalled` (install-time seeding for Power Automate and Power Apps keys when needed, then reconcile on every install/update). Each run reads sync storage, configures `PowerAutomateUrlPolicy`, requests a **toolbar badge** update (`chrome.action`), then calls `declarativeNetRequest.updateEnabledRulesets`. If that DNR call throws after the prior steps, the failure is logged to the console; the policy is configured and the badge update has been requested. Together with manifest defaults, reconcile restores the correct DNR ruleset state after an extension update even when the browser resets static ruleset enablement.
- **Power Apps form enforcement:** Sync keys **`powerAppsHiddenFields`** (`hide` / `show`) and **`powerAppsReadOnly`** (`lock` / `unlock`) are saved from the popup (`persist-powerapps-preference.ts`). When revealing or enabling is active, **`apply-preferences.ts`** calls `chrome.scripting.executeScript` with `world: "MAIN"` and `allFrames: true` on every matching tab (debounced per tab, with bounded retries while Xrm form context is unavailable). The browser attempts injection in all permitted frames; inaccessible frames are not inspected. Triggers: `chrome.storage.onChanged` (fan-out), `tabs.onUpdated` (`complete`), **`content-powerapps.js`** messages (`SCHEDULE_APPLY` on startup, `popstate`, preference changes, and short-lived watchdog URL changes), and the popup apply message **`APPLY_PREFERENCES_ACTIVE_TAB`** (shorter in-popup retries via `POPUP_ACTIVE_TAB_RETRY_DELAYS_MS` while **Applying…** is shown). **`format-powerapps-preferences.ts`** maps apply results to `{ message, variant }` for **`PopupNotificationRegion`**; retryable form-context and injection misses become informational deferred outcomes, while non-retryable host, permission, and messaging failures remain errors. Manifest `host_permissions` list one Chrome-valid org-host pattern per Dataverse suffix in [Microsoft's region table](https://learn.microsoft.com/en-us/power-platform/admin/new-datacenter-regions), snapshot checked July 17, 2026 (e.g. `https://*.crm17.dynamics.com/*`, `https://*.crm.dynamics.cn/*`), plus `apps.powerapps.com`; Web API shards are intentionally excluded. Keep `public/manifest.json` in sync with `src/powerapps/constants.ts` (local drift tests). Patterns like `*.*.dynamics.com` are invalid in Chrome. Only the serialized **`powerAppsFormActionInPage`** function runs in-page (all helpers are nested inside it so injection does not lose scope). Returned frame results are merged; the best success count wins, otherwise `no_form_context` or `no_controls_updated` is preferred over generic failures. User-facing popup strings omit a separate frame-count summary, although optional diagnostic detail may be appended. `inject_no_result` means no permitted frame returned a result (often because the tab is not on a record form or an applicable frame was inaccessible). `host_not_permitted` means the browser blocked injection for the current URL; the recovery message asks the user to confirm site access and reload the extension if available.
- **Executable code** is fully bundled in the package (no remotely hosted extension logic), consistent with MV3 security expectations.
- JSON does not allow `//` comments in `manifest.json`; details live in this README.

## Known limitations

- URL enforcement applies only when pathname contains `/flows/` or `/runs/`, and not while the extension is **paused**.
- **`v3survey` (Power Automate survey settings, while enforcing):** **Hide** (default) sets `v3survey=false` on rewrites (adds if missing). **Show** normalizes any existing `v3survey` keys to a single `true` only; it does not add `v3survey` when missing. Nothing runs while **Paused**.
- If Power Automate changes hostnames or route structures, matching rules may need updates.
- **Power Apps (model-driven forms):** Actions run only on an open **record form** in a model-driven app on a [Microsoft datacenter org host](https://learn.microsoft.com/en-us/power-platform/admin/new-datacenter-regions) (`{org}.crm17.dynamics.com`, `{org}.crm.dynamics.cn`, `{org}.crm.microsoftdynamics.de`, …) or `apps.powerapps.com`. Host permissions cover the Dataverse organization suffixes in the Microsoft table snapshot checked July 17, 2026 (see `DATAVERSE_ORG_HOST_SUFFIXES` in `src/powerapps/constants.ts`; validated in `tests/powerapps-datacenter-regions.test.ts`). **Canvas apps**, list views, dashboards, and maker portals are not supported. Revealing/enabling uses the Xrm Client API (`setVisible` / `setDisabled`) only on tabs, sections, and controls exposed by that API; elements removed in the form designer cannot be revealed. **Field-level security** and platform scripts may keep controls disabled or block saves after enabling them. The floating popup notification shows success counts, informational guidance when an active-tab apply could not complete, action-specific “nothing to change” information, and specific errors with recovery steps. **Keep hidden** stops automatic revealing; **Keep disabled** stops automatic unlocking. Turning one off does not disable the other action, and neither setting can programmatically undo earlier changes—**reload the page** on open record forms to restore platform defaults.

## Validation checklist

After `npm run build`, load **`dist`** unpacked and verify:

- **Classic designer:** links that would open the new designer should open classic instead; links with no editor hint should gain classic. **`v3survey`:** with **Hide** (default), rewrites include **`v3survey=false`**; with **Show**, an existing `v3survey` on the URL becomes **`true`** (never added when absent).
- **New designer:** the same idea with roles flipped: links should land in the new designer, and **`v3survey`** behavior matches **Hide** / **Show** above.
- **Paused:** no link changes; both DNR rulesets off; the in-page watcher is idle; the toolbar badge is cleared.
- **Popup:** opens at **800×600**; each tab’s content scrolls in one full-height panel below the tab bar (not three stacked short bands). Header shows the **ppconfigurator** icon and product name with version; tab marks use **`TabProductIcon`**, and the active tab has a filled surface plus red underline. All settings share full-row **`SettingsChoiceRow`** choice cards. Section descriptions are quiet supporting text by default; the disabled-controls security note uses **`SettingsInfoAlert`**. On first open, saved policy + Power Apps prefs appear immediately (**`POPUP_SYNC_SETTINGS_KEYS`** preload in **`App.tsx`**). **About → Developer** links to Helvety at the bottom. On **Power Automate**, switching Classic Designer / New Designer saves right away (queued if you click quickly) and may refresh the active flow or run tab in the last-focused window; radios stay enabled. A floating alert anchored below the tabs shows **Saving preference…** / **Refreshing the active Power Automate tab…** / **Saved.** without shifting panel content. Changing survey (`v3survey`) options saves the same way; the active flow/run tab may reload only when a designer mode is active (not while Paused). On **Power Apps**, every radio change saves to sync; reopen the popup and confirm the chosen revealing/enabling modes remain selected without a flash of defaults. On an open **record form** tab (e.g. `https://oms-test.crm17.dynamics.com/...` or `apps.powerapps.com`), choose **Reveal hidden elements** or **Enable disabled controls** and confirm the notification shows success counts, informational active-tab guidance, action-specific “nothing to change” copy, or a specific error. Open a second Dataverse tab or fully load another record form—revealed elements should be revealed while that preference is active. A late same-document record change may require a page reload. Choose **Keep hidden** or **Keep disabled** and confirm that corresponding automatic action stops; reload open record forms to restore platform defaults. You can switch popup tabs during a flow/run reload; radios remain clickable while the notification shows progress for the active tab only. **About → Appearance** saves to this device only (`chrome.storage.local`). Background and content react when `enforcedV3`, `v3surveyEnabled`, or Power Apps preference keys change in sync storage; the service worker refreshes the **C** / **N** toolbar badge (or clears it when Paused) on Power Automate reconciles and re-applies active Power Apps prefs when `powerAppsHiddenFields` / `powerAppsReadOnly` change.
- After packaging an update, confirm DNR ruleset enablement still matches the saved preference (service worker load and `chrome.runtime.onInstalled` both reconcile via the policy queue).
