# Power Platform Configurator

**Public summary** (matches manifest `description`, max 132 characters): Power Automate flow URLs (classic/new, survey). Unhide or unlock fields on model-driven Power Apps forms. Survey **Hide** / **Show**, `v3` flags, and full behavior are documented below and on the Helvety Store listing (`POWER_PLATFORM_CONFIGURATOR_STORE_SHORT_DESCRIPTION`).

That one-line blurb covers both popup product areas. The popup **Power Automate** tab still supports survey **Show**, which normalizes an existing `v3survey` key on the URL to `true` without adding the parameter when it is absent—see **What it does** and **Known limitations** for the full rules.

Chrome/Edge extension (Manifest V3) that **keeps flow and run links opening in the editor you choose** while the extension is active: classic (`v3=false`) or new designer (`v3=true`), even when Microsoft links omit or flip the flag. You can **pause** anytime (extension stays installed; no URL rewrites or DNR rules). **Declarative Net Request** rules only add or replace the **`v3`** query parameter on matching navigations; the **service worker** and **content script** apply the full URL policy from sync, including **`v3survey`** from the popup **Power Automate** tab (sync key `v3surveyEnabled`). Microsoft sometimes uses **`v3survey`** for an in-product **classic-designer survey** prompt. **Hide** (default, sync `"false"`) sets **`v3survey=false`** on rewrites (adds the param if missing). **Show** (sync `"true"`) normalizes any existing `v3survey` query keys on the URL to a single **`v3survey=true`** and does **not** add the param when it is absent.

On **model-driven Power Apps** hosts (`*.crm.dynamics.com`, `apps.powerapps.com`), the popup **Power Apps** tab can **unhide hidden fields** or **unlock read-only fields** on the open record form via the Xrm Client API (client-side only; canvas apps are not supported).

## What it does

- Runs on Microsoft Power Automate hosts:
  - `https://*.powerautomate.com/*`
  - `https://flow.microsoft.com/*`
- Only changes URLs whose path contains `/flows/` or `/runs/` (and only while enforcement is **not** paused).
- **Toolbar popup** (React + Tailwind + Radix): header shows the packaged **`ppconfigurator_*`** icon and **Power Platform Configurator** with the manifest version (`PopupHeader` wraps `@helvety/extension-chrome/popup-header`). Tabs: **Power Automate**, **Power Apps**, and **About**. The **Power Automate** tab combines flow designer (**Classic Designer**, **New Designer**, or **Paused**), survey prompt Hide/Show (`v3survey`), and the Flow Inspector launcher. Your designer choice is stored in `chrome.storage.sync` under `enforcedV3` as `"true"`, `"false"`, or `"off"` and applied in the service worker, content script, and DNR layer. If Chrome sync is off, `chrome.storage.sync` still works for that profile; it behaves like local storage ([Chrome `storage` docs](https://developer.chrome.com/docs/extensions/reference/api/storage/)). The service worker mirrors that preference on the **browser toolbar icon** as a small **C** / **N** badge (via `chrome.action`), or clears the badge while **Paused**. The **Power Apps** tab runs one-shot **Unhide hidden fields** / **Unlock read-only fields** on the active model-driven form tab (`src/powerapps/`, `src/background/powerapps-router.ts`). **About** ends with a **Developer** block (Helvety logo and link to [helvety.com](https://helvety.com)). **Popup appearance** (About tab: **Light** or **Dark**; first open picks from the OS, then the choice is stored) lives in **`chrome.storage.local`** under `popupThemePreference` so it stays on this device and does not sync across signed-in browsers. Before React, `@helvety/extension-chrome/theme-boot` applies the OS `prefers-color-scheme` to `<html>` only (MV3 extension CSP; no inline script); the popup then applies the saved **Light** / **Dark** from storage via `usePopupTheme`.
- **Save feedback (Power Automate):** phased status (**Saving preference…** → **Refreshing open Power Automate tab…** when applicable → **Saved.**) plus spinners during the **`chrome.storage.sync.set`** write and, separately, during an optional **`chrome.tabs.reload`** of the last-focused **flow/run** tab (`src/popup/reload-focused-target-tab.ts`; returns whether reload ran, for status auto-dismiss timing). Flow designer / survey radio groups are disabled only while the sync write is in flight; **tab triggers stay enabled** so you can switch tabs while a reload runs. Rapid toggles on the same surface are **serialized** (one **`createAsyncQueue`** each for flow designer vs survey saves in `src/popup/sync-write-queue.ts`) so `chrome.storage.sync.set` calls cannot reorder. Shared save/reload logic lives in `src/popup/persist-policy-preference.ts` (wired from `App.tsx`). In **development** popup builds, optional `console.log` traces use the prefix `[power-platform-configurator] [popup]` (`policy-popup-log.ts` and the reload helper; gated by `import.meta.env.DEV`).
- **Declarative Net Request** static rulesets only add or replace the **`v3`** query parameter on matching **main_frame** requests (they do not read **`v3surveyEnabled`** from storage and do not change **`v3survey`**).
- The **service worker** and **content script** read `enforcedV3` and `v3surveyEnabled` from sync and run `PowerAutomateUrlPolicy`: they keep **`v3`** aligned with your editor choice. **`v3survey`**: **Hide** (default, sync `"false"`) sets **`v3survey=false`** (adds if missing) on rewrites. **Show** (sync `"true"`) collapses duplicate keys to a single **`v3survey=true`** only when the URL already had `v3survey`; it never adds the param when absent. Sync key: `v3surveyEnabled` (`"true"` / `"false"`).
- Uses semantic URL dedupe to avoid rewrite loops on equivalent `/flows/new` URLs (for example `%20` vs `+` encoding differences).
- **Layered enforcement** (aligned with Chromium MV3 best practices):
  - **Layer 1:** `declarativeNetRequest`: two static rulesets (`dnr-classic-editor.json`, `dnr-new-designer.json`); each rule’s `queryTransform` only sets **`v3`**. When enforcing, **exactly one** ruleset is enabled via `updateEnabledRulesets`; when **paused**, **both** are disabled. When the service worker loads (cold start, wake from idle, or after an extension update), it reconciles enabled rulesets with storage (Chromium does not persist which static rulesets were enabled across extension updates; the manifest defaults apply until the service worker runs again; see [Declarative Net Request](https://developer.chrome.com/docs/extensions/reference/api/declarativeNetRequest)).
  - **Layer 2:** Background `webNavigation` (`onCommitted`, `onHistoryStateUpdated`) runs the full stored URL policy (including **`v3survey`** per **Hide** / **Show**) via `tabs.update` when enforcement is active (same canonicalization as the content script; no-op when paused).
  - **Layer 3:** Content script at `document_start` for SPA transitions (`history.pushState` / `replaceState`, `popstate`, short-lived polling + `MutationObserver`) when enforcement is active, applying the same full policy as Layer 2 (polling/observer are not started while paused). `MutationObserver` callbacks are coalesced to at most one canonicalization per animation frame to reduce main-thread churn.

## Flow Inspector (side panel)

- **Two surfaces:** the **toolbar popup** (Power Automate / Power Apps / About settings) and the **side panel** (Flow Inspector). They are separate on purpose—Chrome’s side panel is full-height and stays open beside your tab; the popup is small and closes when you click away.
- **Side panel** (`inspector.html`, Chrome 114+): browse **environments → flows → runs → run detail** with expandable actions, inputs, outputs, and errors — while keeping your main tab on whatever you are editing.
- **No extension login:** reuses your existing Power Automate browser session via a **content-script session bridge** on an open `*.powerautomate.com` / `flow.microsoft.com` tab. If no session is available, the inspector prompts you to **Open Power Automate** (normal portal sign-in), not an OAuth popup inside the extension.
- **Open from popup:** Power Automate tab → **Open Flow Inspector side panel** (the popup closes so you can use the panel). You can also open the inspector from Chrome’s side panel menu for this extension.
- **Sync from tab:** when your active tab is a flow or run URL, use **Sync from tab** to jump to that context in the inspector.
- **APIs:** official Power Platform API (`api.powerplatform.com`) for environments, flows, and run lists; portal-equivalent run-action APIs (`api.flow.microsoft.com`, unsupported by Microsoft) for per-action inputs/outputs.
- **Read-only** in v1 (no resubmit/cancel). Requires at least one signed-in Power Automate tab for the session bridge.

### Flow Inspector limitations

- Run action I/O depends on unsupported portal APIs and may break if Microsoft changes them.
- Official APIs may not list every flow visible under **My Flows** in the portal; a portal API fallback is used when needed.
- Conditional Access / MFA can block silent token refresh — interact with your Power Automate tab to restore the session.
- Side panel width is user-resizable (roughly 300–600px); layout is optimized for narrow viewports.

## Helvety workspace packages (`npm install`)

The popup imports **`@helvety/extension-chrome`**, **`@helvety/ui`**, **`@helvety/shared`**, and **`@helvety/brand`** from a vendored copy under **`.helvety/`** (gitignored). `preinstall` runs `scripts/ensure-helvety.mjs`:

- If **`../helvety`** exists: **copies** `packages/{shared,ui,brand,extension-chrome,config}` into `.helvety/packages/` (never symlinks into the monorepo, so `patch-helvety-workspace-deps.mjs` cannot mutate sibling repos).
- Otherwise: reuses or shallow-clones `.helvety/` from GitHub, then patches `workspace:*` → `file:../` inside **`.helvety/packages` only**.

Popup primitives (tabs, radio groups, buttons) come from **`@helvety/ui`**, not app-local `src/components/ui`. `components.json` aliases point at those packages for optional shadcn CLI use.

## Build and load (development)

Source lives under `src/`. The loadable extension is produced in **`dist/`** after a build.

1. Install dependencies and build:

   ```bash
   npm install
   npm run build
   ```

2. Open `chrome://extensions` (Chrome) or `edge://extensions` (Edge), enable **Developer mode**, click **Load unpacked**, and select the **`dist`** folder (not the repository root).

3. After changing anything under `src/`, `public/`, or build config, run `npm run build` again before reloading the extension in the browser (the unpacked folder must be **`dist/`**, which is replaced on each full build).

## Browser compatibility

- Manifest V3 extension intended for Chromium-based browsers (Chrome, Edge, Brave, Arc, Opera, etc.).
- Requires: `declarativeNetRequest`, `webNavigation`, `scripting`, `storage`, `sidePanel`, `tabs`, and `host_permissions` for Power Automate, Power Platform APIs, and model-driven hosts (`*.crm.dynamics.com`, `apps.powerapps.com`). Content scripts on Power Automate use the History API and `MutationObserver`; Power Apps form actions use `chrome.scripting.executeScript` in the MAIN world. See [tabs](https://developer.chrome.com/docs/extensions/reference/api/tabs) and [scripting](https://developer.chrome.com/docs/extensions/reference/api/scripting).

## Implementation notes

- **Service worker listeners** (`webNavigation`, `tabs.onRemoved`, `storage.onChanged`, `runtime.onInstalled`) are registered at the **top level** of `background.ts`, per Google’s MV3 guidance (avoid registering listeners only inside async callbacks). `webNavigation` handlers are `async` and **`await policyQueue.awaitReconcileCaughtUp()`** before running URL logic so policy is never applied from stale default module state ahead of the first `chrome.storage.sync.get` (see `src/policy-load-queue.ts`).
- **Popup policy saves** (`persist-policy-preference.ts`, called from `App.tsx`): after each successful `chrome.storage.sync.set` for `enforcedV3` or `v3surveyEnabled`, the sync-write spinner clears so the UI stays responsive; the popup then awaits `reloadFocusedTargetTabIfApplicable` (when enforcement is not **Paused**) before showing **Saved.** The helper’s **boolean** return still drives status auto-dismiss timing (longer only when `chrome.tabs.reload` actually ran). Flow designer and survey saves each use a **`createAsyncQueue`** tail so rapid clicks serialize storage writes. Pending dismiss timers are cleared when a new save starts or the popup unmounts.
- **`reconcileFromStorage()`** is queued by **`createPolicyLoadQueue`**: an initial run happens when the service worker loads; further runs are chained from `chrome.storage.onChanged` (for `enforcedV3` / `v3surveyEnabled`) and from `chrome.runtime.onInstalled` (install-time seeding when needed, then reconcile on every install/update). Each run reads sync storage, configures `PowerAutomateUrlPolicy`, updates the **toolbar badge** (`chrome.action`), then calls `declarativeNetRequest.updateEnabledRulesets`. If that DNR call throws after the prior steps, the failure is logged to the console; policy state and the badge already match storage. Together with manifest defaults, reconcile restores the correct DNR ruleset state after an extension update even when the browser resets static ruleset enablement.
- **Executable code** is fully bundled in the package (no remotely hosted extension logic), consistent with MV3 security expectations.
- JSON does not allow `//` comments in `manifest.json`; details live in this README.

## Known limitations

- URL enforcement applies only when pathname contains `/flows/` or `/runs/`, and not while the extension is **paused**.
- **`v3survey` (Power Automate survey settings, while enforcing):** **Hide** (default) sets `v3survey=false` on rewrites (adds if missing). **Show** normalizes any existing `v3survey` keys to a single `true` only; it does not add `v3survey` when missing. Nothing runs while **Paused**.
- If Power Automate changes hostnames or route structures, matching rules may need updates.

## Validation checklist

After `npm run build`, load **`dist`** unpacked and verify:

- **Classic designer:** links that would open the new designer should open classic instead; links with no editor hint should gain classic. **`v3survey`:** with **Hide** (default), rewrites include **`v3survey=false`**; with **Show**, an existing `v3survey` on the URL becomes **`true`** (never added when absent).
- **New designer:** the same idea with roles flipped: links should land in the new designer, and **`v3survey`** behavior matches **Hide** / **Show** above.
- **Paused:** no link changes; both DNR rulesets off; the in-page watcher is idle; the toolbar badge is cleared.
- **Popup:** header shows the **ppconfigurator** icon and product name with version; tab marks use **`TabProductIcon`** (Power Automate / Power Apps SVGs). **About → Developer** links to Helvety at the bottom. On **Power Automate**, switching Classic Designer / New Designer saves right away (queued if you click quickly) and may refresh the flow or run tab you had focused. Changing survey (`v3survey`) options saves immediately the same way; the active flow/run tab may reload only when a designer mode is active (not while Paused). On **Power Apps**, use the action buttons on an open model-driven form tab. You can switch popup tabs during a flow/run reload; designer/survey radios briefly disable only while the sync write runs. **About → Appearance** saves to this device only (`chrome.storage.local`). Background and content still react when `enforcedV3` or `v3surveyEnabled` changes in sync storage; the service worker also refreshes the **C** / **N** toolbar badge (or clears it when Paused) on those reconciles.
- After packaging an update, confirm DNR ruleset enablement still matches the saved preference (service worker load and `chrome.runtime.onInstalled` both reconcile via the policy queue).
