# Power Platform Configurator

**Public summary** (matches manifest `description`, max 132 characters): Power Automate flow URLs (classic/new, survey). Unhide or unlock fields on model-driven Power Apps forms. Survey **Hide** / **Show**, `v3` flags, and full behavior are documented below and on the Helvety Store listing (`POWER_PLATFORM_CONFIGURATOR_STORE_SHORT_DESCRIPTION`).

That one-line blurb covers both popup product areas. The popup **Power Automate** tab still supports survey **Show**, which normalizes an existing `v3survey` key on the URL to `true` without adding the parameter when it is absent—see **What it does** and **Known limitations** for the full rules.

Chrome/Edge extension (Manifest V3) that **keeps flow and run links opening in the editor you choose** while the extension is active: classic (`v3=false`) or new designer (`v3=true`), even when Microsoft links omit or flip the flag. You can **pause** anytime (extension stays installed; no URL rewrites or DNR rules). **Declarative Net Request** rules only add or replace the **`v3`** query parameter on matching navigations; the **service worker** and **content script** apply the full URL policy from sync, including **`v3survey`** from the popup **Power Automate** tab (sync key `v3surveyEnabled`). Microsoft sometimes uses **`v3survey`** for an in-product **classic-designer survey** prompt. **Hide** (default, sync `"false"`) sets **`v3survey=false`** on rewrites (adds the param if missing). **Show** (sync `"true"`) normalizes any existing `v3survey` query keys on the URL to a single **`v3survey=true`** and does **not** add the param when it is absent.

On **model-driven Power Apps** hosts (every [Microsoft datacenter org URL](https://learn.microsoft.com/en-us/power-platform/admin/new-datacenter-regions)—e.g. `{org}.crm17.dynamics.com`, `{org}.crm.dynamics.cn`, `{org}.crm.microsoftdynamics.de`—plus `apps.powerapps.com`), the popup **Power Apps** tab uses the same radio settings as Power Automate: **Hide hidden fields** / **Show hidden fields** and **Lock read-only** / **Unlock read-only**. Choices persist in **`chrome.storage.sync`** (`powerAppsHiddenFields`, `powerAppsReadOnly`) and stay enforced across tabs and record navigation until you switch back to **Hide** or **Lock**. **Show** / **Unlock** inject a self-contained MAIN-world script that calls the Xrm Client API on each eligible **record form** (client-side only; canvas apps are not supported). **Hide** / **Lock** stop auto-apply; reload open forms to restore platform defaults. A **notification area** below the tab bar (styled **`SettingsStatusAlert`**, only on the active product tab) reports success counts, a blue reload hint when the form is still loading (preference already saved), or specific red errors (wrong host, inject failed, reload the extension when the tab URL is not permitted after an update).

## What it does

- Runs on Microsoft Power Automate hosts:
  - `https://*.powerautomate.com/*`
  - `https://flow.microsoft.com/*`
- Only changes URLs whose path contains `/flows/` or `/runs/` (and only while enforcement is **not** paused).
- **Toolbar popup** (React + Tailwind + Radix): sized to Chrome’s maximum popup (**800×600** px). Header shows the packaged **`ppconfigurator_*`** icon and **Power Platform Configurator** with the manifest version (`PopupHeader` wraps `@helvety/extension-chrome/popup-header`). Tabs: **Power Automate**, **Power Apps**, and **About**. Between the tab bar and the scrollable panels, a shared **notification slot** (`PopupNotificationRegion` + **`SettingsStatusAlert`**) shows save/apply feedback for the **active** product tab only (collapses when empty). Tab bodies use **`SettingsTabPanel`** (shared scroll shell: `TAB_PANEL_HOST_CLASS` + stacked `TabsContent` layers in `popup-layout.ts`, not three flex-split bands). All settings use **`SettingsChoiceRow`** / **`SettingsSectionHeader`** with spacing tokens from **`popup-layout.ts`** (`settingsChoiceRowClass`, `SETTINGS_RADIO_GROUP_CLASS`, …)—not the legacy `@helvety/extension-chrome/popup-shell` row helper. Each **`SettingsChoiceRow`** wraps the radio, title, and description in one **`Label`** so the full row is clickable. Section descriptions use bordered **`SettingsInfoAlert`** callouts; **`SettingsBusyHint`** on section headers appears only when the notification slot is idle (avoids duplicate **Saving…** / **Applying…** copy). Before the main UI renders, **`App.tsx`** loads flow designer, survey, and Power Apps prefs in one **`POPUP_SYNC_SETTINGS_KEYS`** read (popup theme via **`usePopupTheme`** separately). The **Power Automate** tab combines flow designer (**Classic Designer**, **New Designer**, or **Paused**) and survey prompt Hide/Show (`v3survey`). Your designer choice is stored in `chrome.storage.sync` under `enforcedV3` as `"true"`, `"false"`, or `"off"` and applied in the service worker, content script, and DNR layer. If Chrome sync is off, `chrome.storage.sync` still works for that profile; it behaves like local storage ([Chrome `storage` docs](https://developer.chrome.com/docs/extensions/reference/api/storage/)). The service worker mirrors that preference on the **browser toolbar icon** as a small **C** / **N** badge (via `chrome.action`), or clears the badge while **Paused**. The **Power Apps** tab uses the same **radio** settings pattern as Power Automate (**Hide** / **Show** hidden fields, **Lock** / **Unlock** read-only). Prefs sync globally; the service worker and **`content-powerapps.js`** re-apply **Show** / **Unlock** on every Dataverse tab load, SPA navigation, and preference change via **`applyPowerAppsPreferencesOnTab`** (`chrome.scripting.executeScript`, MAIN world, all frames, self-contained **`powerAppsFormActionInPage`** in `src/powerapps/`). **`App.tsx`** owns Power Apps status timers; saves and active-tab apply results surface in the notification slot (`persist-powerapps-preference.ts`, `powerapps-client.ts`, `powerapps-router.ts`). **About** ends with a **Developer** block (Helvety logo and link to [helvety.com](https://helvety.com)). **Popup appearance** (About tab: **Light** or **Dark**; first open picks from the OS, then the choice is stored) lives in **`chrome.storage.local`** under `popupThemePreference` so it stays on this device and does not sync across signed-in browsers. Before React, `@helvety/extension-chrome/theme-boot` applies the OS `prefers-color-scheme` to `<html>` only (MV3 extension CSP; no inline script); the popup then applies the saved **Light** / **Dark** from storage via `usePopupTheme`.
- **Save feedback (Power Automate):** phased messages (**Saving preference…** → **Refreshing open Power Automate tab…** when applicable → **Saved.** / **Saved. Reloaded the open flow or run page.** / **Saved. Reload the flow or run page to apply.**) in the notification slot during **`chrome.storage.sync.set`** and, separately, during an optional **`chrome.tabs.reload`** of the last-focused **flow/run** tab (`src/popup/reload-focused-target-tab.ts`; returns whether reload ran, for auto-dismiss timing). Flow designer and survey **radio groups stay enabled** during saves. **Tab triggers stay enabled** so you can switch tabs during a reload. Rapid toggles on the same surface are **serialized** (one **`createAsyncQueue`** each for flow designer vs survey saves in `src/popup/sync-write-queue.ts`) so `chrome.storage.sync.set` calls cannot reorder. Shared save/reload logic lives in `src/popup/persist-policy-preference.ts` (wired from `App.tsx`; status strings in `persist-status-messages.ts`).
- **Save feedback (Power Apps):** **`App.tsx`** owns hidden/read-only state, status timers, and busy flags from the shared preload; **`PowerAppsPanel`** is controlled and writes **`powerAppsHiddenFields`** and **`powerAppsReadOnly`** via **`persist-powerapps-preference.ts`** (serialized with **`createAsyncQueue`** in the panel). Radios stay enabled during save/apply. When **Show** or **Unlock** is active, the notification slot shows **Saving preference…** then **Applying…** with results from the active tab (`APPLY_PREFERENCES_ACTIVE_TAB`, including short in-popup retries). **`format-powerapps-preferences.ts`** supplies explicit alert **`variant`** values (info vs error); Power Automate still infers variant from message text when omitted. If the record form is still loading, you may see a blue **Preference saved. Reload the page to apply on this record form.** message even though sync saved—the service worker keeps retrying on tab load/navigation. **Hide** / **Lock** save without applying and prompt **Reload the page** on open record forms. Hard failures (wrong host, save/apply errors) stay red and also ask you to **Reload the page** when retry may help. The service worker and **`content-powerapps.js`** keep enforcing **Show** / **Unlock** on all open Dataverse tabs until you switch back. In **development** popup builds, optional `console.log` traces use the prefix `[power-platform-configurator] [popup]` (`policy-popup-log.ts` and the reload helper; gated by `import.meta.env.DEV`).
- **Declarative Net Request** static rulesets only add or replace the **`v3`** query parameter on matching **main_frame** requests (they do not read **`v3surveyEnabled`** from storage and do not change **`v3survey`**).
- The **service worker** and **content script** read `enforcedV3` and `v3surveyEnabled` from sync and run `PowerAutomateUrlPolicy`: they keep **`v3`** aligned with your editor choice. **`v3survey`**: **Hide** (default, sync `"false"`) sets **`v3survey=false`** (adds if missing) on rewrites. **Show** (sync `"true"`) collapses duplicate keys to a single **`v3survey=true`** only when the URL already had `v3survey`; it never adds the param when absent. Sync key: `v3surveyEnabled` (`"true"` / `"false"`).
- Uses semantic URL dedupe to avoid rewrite loops on equivalent `/flows/new` URLs (for example `%20` vs `+` encoding differences).
- **Layered enforcement** (aligned with Chromium MV3 best practices):
  - **Layer 1:** `declarativeNetRequest`: two static rulesets (`dnr-classic-editor.json`, `dnr-new-designer.json`); each rule’s `queryTransform` only sets **`v3`**. When enforcing, **exactly one** ruleset is enabled via `updateEnabledRulesets`; when **paused**, **both** are disabled. When the service worker loads (cold start, wake from idle, or after an extension update), it reconciles enabled rulesets with storage (Chromium does not persist which static rulesets were enabled across extension updates; the manifest defaults apply until the service worker runs again; see [Declarative Net Request](https://developer.chrome.com/docs/extensions/reference/api/declarativeNetRequest)).
  - **Layer 2:** Background `webNavigation` (`onCommitted`, `onHistoryStateUpdated`) runs the full stored URL policy (including **`v3survey`** per **Hide** / **Show**) via `tabs.update` when enforcement is active (same canonicalization as the content script; no-op when paused).
  - **Layer 3:** Content script at `document_start` for SPA transitions (`history.pushState` / `replaceState`, `popstate`, short-lived polling + `MutationObserver`) when enforcement is active, applying the same full policy as Layer 2 (polling/observer are not started while paused). `MutationObserver` callbacks are coalesced to at most one canonicalization per animation frame to reduce main-thread churn.

## Helvety workspace packages (`npm install`)

The popup imports **`@helvety/extension-chrome`**, **`@helvety/ui`**, and **`@helvety/shared`** from a vendored copy under **`.helvety/`** (gitignored). `preinstall` runs `scripts/ensure-helvety.mjs`:

- If **`../helvety`** exists: **copies** `packages/{shared,ui,brand,extension-chrome,config}` into `.helvety/packages/` (never symlinks into the monorepo, so `patch-helvety-workspace-deps.mjs` cannot mutate sibling repos).
- Otherwise: reuses or shallow-clones `.helvety/` from GitHub, then patches `workspace:*` → `file:../` inside **`.helvety/packages` only**.

Popup primitives (tabs, `RadioGroup` / `RadioGroupItem`, labels) come from **`@helvety/ui`**, not app-local `src/components/ui`. Local shadcn-style **`Alert`** lives in **`src/popup/components/ui/alert.tsx`** for **`SettingsStatusAlert`** and **`SettingsInfoAlert`**. Shared padding, section rhythm, choice-card rows, notification region classes (`pt-2` below the tab bar), tab shells (**`SettingsTabPanel`**), and **`SettingsBusyHint`** live in **`src/popup/popup-layout.ts`** and **`SettingsChoiceRow`** / **`SettingsSectionHeader`** (this repo—not `@helvety/extension-chrome/popup-shell`). User-facing save strings are centralized in **`persist-status-messages.ts`**; Power Apps apply outcomes are formatted in **`format-powerapps-preferences.ts`**. `components.json` maps shadcn CLI aliases to local popup components and Helvety `ui` / `utils`.

## Build and load (development)

Source lives under `src/`. The loadable extension is produced in **`dist/`** after a build.

1. Install dependencies and build:

   ```bash
   npm install
   npm run build
   ```

2. Open `chrome://extensions` (Chrome) or `edge://extensions` (Edge), enable **Developer mode**, click **Load unpacked**, and select the **`dist`** folder (not the repository root).

3. After changing anything under `src/`, `public/`, or build config, run `npm run build` again before reloading the extension in the browser (the unpacked folder must be **`dist/`**, which is replaced on each full build).

## Browser compatibility

- Manifest V3 extension intended for Chromium-based browsers (Chrome, Edge, Brave, Arc, Opera, etc.).
- Requires: `declarativeNetRequest`, `webNavigation`, `scripting`, `storage`, `tabs`, and `host_permissions` for Power Automate and model-driven hosts (per-cluster patterns such as `https://*.crm17.dynamics.com/*` for `{org}.crm17.dynamics.com`, plus `apps.powerapps.com`). Chrome rejects multi-wildcard hosts like `*.*.dynamics.com`. Content scripts on Power Automate use the History API and `MutationObserver`; Power Apps uses **`content-powerapps.js`** (ISOLATED world) to detect SPA navigation and **`chrome.scripting.executeScript`** in the MAIN world for **Show** / **Unlock** enforcement. See [tabs](https://developer.chrome.com/docs/extensions/reference/api/tabs) and [scripting](https://developer.chrome.com/docs/extensions/reference/api/scripting).

## Implementation notes

- **Service worker listeners** (`webNavigation`, `tabs.onRemoved`, `storage.onChanged`, `runtime.onInstalled`) are registered at the **top level** of `background.ts`, per Google’s MV3 guidance (avoid registering listeners only inside async callbacks). `webNavigation` handlers are `async` and **`await policyQueue.awaitReconcileCaughtUp()`** before running URL logic so policy is never applied from stale default module state ahead of the first `chrome.storage.sync.get` (see `src/policy-load-queue.ts`).
- **Popup policy saves** (`persist-policy-preference.ts`, called from `App.tsx`): after each successful `chrome.storage.sync.set` for `enforcedV3` or `v3surveyEnabled`, the sync-write busy flag clears so radios stay interactive; a **notification area** below the tab bar (styled **`SettingsStatusAlert`**, only on the active product tab) shows **Saving…** / **Reloading tab…** while work runs—section **`SettingsBusyHint`** labels hide during that time to avoid duplicate copy. The popup then awaits `reloadFocusedTargetTabIfApplicable` (when enforcement is not **Paused**) and shows **Saved.**, **Saved. Reloaded the open flow or run page.**, or **Saved. Reload the flow or run page to apply.** depending on whether a tab reload ran. The helper’s **boolean** return still drives status auto-dismiss timing (longer only when `chrome.tabs.reload` actually ran). Flow designer and survey saves each use a **`createAsyncQueue`** tail so rapid clicks serialize storage writes. Pending dismiss timers are cleared when a new save starts or the popup unmounts.
- **`reconcileFromStorage()`** is queued by **`createPolicyLoadQueue`**: an initial run happens when the service worker loads; further runs are chained from `chrome.storage.onChanged` (for `enforcedV3` / `v3surveyEnabled`) and from `chrome.runtime.onInstalled` (install-time seeding for Power Automate and Power Apps keys when needed, then reconcile on every install/update). Each run reads sync storage, configures `PowerAutomateUrlPolicy`, updates the **toolbar badge** (`chrome.action`), then calls `declarativeNetRequest.updateEnabledRulesets`. If that DNR call throws after the prior steps, the failure is logged to the console; policy state and the badge already match storage. Together with manifest defaults, reconcile restores the correct DNR ruleset state after an extension update even when the browser resets static ruleset enablement.
- **Power Apps form enforcement:** Sync keys **`powerAppsHiddenFields`** (`hide` / `show`) and **`powerAppsReadOnly`** (`lock` / `unlock`) are saved from the popup (`persist-powerapps-preference.ts`). When **Show** or **Unlock** is active, **`apply-preferences.ts`** calls `chrome.scripting.executeScript` with `world: "MAIN"` and `allFrames: true` on every matching tab (debounced per tab, with retries until Xrm form context loads). Triggers: `chrome.storage.onChanged` (fan-out), `tabs.onUpdated` (`complete`), **`content-powerapps.js`** messages (`SCHEDULE_APPLY` on SPA/history changes), and the popup apply message **`APPLY_PREFERENCES_ACTIVE_TAB`** (shorter in-popup retries via `POPUP_ACTIVE_TAB_RETRY_DELAYS_MS` while **Applying…** is shown). **`format-powerapps-preferences.ts`** maps apply results to `{ message, variant }` for **`PopupNotificationRegion`** (retryable `no_form_context` → blue deferred-reload info, not a red error). Manifest `host_permissions` list one Chrome-valid pattern per row in [Microsoft’s datacenter table](https://learn.microsoft.com/en-us/power-platform/admin/new-datacenter-regions) (e.g. `https://*.crm17.dynamics.com/*`, `https://*.crm.dynamics.cn/*`) plus matching `https://*.api.{suffix}/*` and `apps.powerapps.com` — keep `public/manifest.json` in sync with `src/powerapps/constants.ts` (CI drift tests). Patterns like `*.*.dynamics.com` are invalid in Chrome. Only the serialized **`powerAppsFormActionInPage`** function runs in-page (all helpers are nested inside it so injection does not lose scope). Results from every frame are merged; the best success count wins, otherwise `no_form_context` or `no_controls_updated` is preferred over generic failures. User-facing popup strings omit per-frame **Checked N frames** hints (`formatPowerAppsActionErrorForNotification` / `formatPowerAppsActionSuccessForNotification`). `inject_no_result` means no frame returned a result (often not on a record form or cross-origin iframe). `host_not_permitted` means Chrome blocked injection until the user reloads the extension on `chrome://extensions` (common right after installing an update with new hosts).
- **Executable code** is fully bundled in the package (no remotely hosted extension logic), consistent with MV3 security expectations.
- JSON does not allow `//` comments in `manifest.json`; details live in this README.

## Known limitations

- URL enforcement applies only when pathname contains `/flows/` or `/runs/`, and not while the extension is **paused**.
- **`v3survey` (Power Automate survey settings, while enforcing):** **Hide** (default) sets `v3survey=false` on rewrites (adds if missing). **Show** normalizes any existing `v3survey` keys to a single `true` only; it does not add `v3survey` when missing. Nothing runs while **Paused**.
- If Power Automate changes hostnames or route structures, matching rules may need updates.
- **Power Apps (model-driven forms):** Actions run only on an open **record form** in a model-driven app on a [Microsoft datacenter org host](https://learn.microsoft.com/en-us/power-platform/admin/new-datacenter-regions) (`{org}.crm17.dynamics.com`, `{org}.crm.dynamics.cn`, `{org}.crm.microsoftdynamics.de`, …) or `apps.powerapps.com`. Host permissions list every Learn table suffix (see `DATAVERSE_ORG_HOST_SUFFIXES` in `src/powerapps/constants.ts`; validated in `tests/powerapps-datacenter-regions.test.ts`). **Canvas apps**, list views, dashboards, and maker portals are not supported. **Show** / **Unlock** use the Xrm Client API (`setVisible` / `setDisabled`) only on controls that are hidden or disabled in the Client API sense; fields removed in the form designer cannot be revealed. **Field-level security** and platform scripts may keep fields read-only or block saves after unlock. The popup **notification area** (below the tab bar) shows success counts, a blue reload hint when the record form is still loading (preference already saved), benign “nothing to change” info, inject failures (often **reload the page**), and red “reload the extension” when the tab URL is not permitted. **Hide** / **Lock** stop enforcement but cannot programmatically undo a prior **Show** / **Unlock**—**reload the page** on open record forms to restore platform defaults.

- **Classic designer:** links that would open the new designer should open classic instead; links with no editor hint should gain classic. **`v3survey`:** with **Hide** (default), rewrites include **`v3survey=false`**; with **Show**, an existing `v3survey` on the URL becomes **`true`** (never added when absent).

- **Paused:** no link changes; both DNR rulesets off; the in-page watcher is idle; the toolbar badge is cleared.
- **Popup:** opens at **800×600**; each tab’s content scrolls in one full-height panel below the tab bar and notification slot (not three stacked short bands). Header shows the **ppconfigurator** icon and product name with version; tab marks use **`TabProductIcon`**. On **Power Apps**, every radio change saves to sync; reopen the popup and confirm **Show** / **Unlock** stay selected without a flash of defaults. On an open **record form** tab (e.g. `https://oms-test.crm17.dynamics.com/...` or `apps.powerapps.com`), choose **Show hidden fields** or **Unlock read-only** and confirm the notification area (success with counts, a blue **Preference saved.
